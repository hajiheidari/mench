# Multiplayer v1 (M4–M5)

Clients send strict version-1 intents with UUID request IDs. Server controls all dice, legal moves, turns, captures and outcomes. Snapshot events include authoritative state version. Stale versions, forged dice fields, wrong owner/turn, malformed payloads and unsupported protocols fail. Request IDs are cached per member (128 most recent); clients must not reuse old IDs after this bound. A version still prevents an old move from applying after cache expiry. No client-specified outcomes are accepted.
Socket.IO handles heartbeat (5s ping/10s timeout); a room-scoped 256-bit bearer capability resumes a guest. Only token hashes are kept by the room service; public snapshots expose none. A resumed session disconnects the previous socket. Browser stores token in sessionStorage, not URL. Refresh restores snapshot/version/history. Losing a browser tab's storage loses guest access; accounts will offer persistent identity separately.
Turn deadline is 30s; current disconnected player gets at least 45s grace. Server preserves game on disconnect. Grace expiry advances a turn rather than destroying the match. Time is injected for tests. Snapshots replace event deltas at current scale and avoid event-cursor holes. With DATABASE_URL, private snapshots and command audit events commit in one PostgreSQL transaction before acknowledgment or broadcast. Restart restores identities, token hashes, game state, proof history and pending secret commitment; all players initially disconnect and receive grace. Raw resume tokens and response caches never enter the database. Request-response caching is bounded and process-local; clients must resume and use the restored version after restart. Durable replay of old acknowledgments is not provided. Database write failure freezes gameplay and makes health return 503; restart requires resolving the database fault. Backups contain unrevealed seeds and require restricted access. Without a database, the test adapter is explicitly ephemeral.
Commands, disconnects and timers run through one serialized actor on one Node process; engine transitions are synchronous, persistence is awaited. Pending jobs are bounded at 2000. Current deployment is single-instance; do not start multiple room owners behind a load balancer. Strict origin allowlist, 16KB inbound frame cap and 100 commands per 10s per socket. 1000 rooms and 24h TTL. Queue is in-memory and bounded. Production needs distributed ownership, per-identity/global abuse budgets and multi-instance coordination.
Node integration tests use real Socket.IO clients. Full accelerated 2/4-player games use a raised configurable command budget; a separate default-budget test verifies spam rejection. Tests verify every roll, duplicate requests, false dice fields and unauthorized moves. Clock tests cover disconnect 2/10/30s and grace expiry; actual socket tests cover session replacement/reconnect. PostgreSQL integration tests cover shutdown with connected sockets, restart recovery and fail-closed write failures.

Registered-member resume additionally requires the matching live account session. Logout/suspension/deletion disconnect corresponding account sockets; revocation cannot be bypassed using an old registered room capability. Anonymous members retain their guest-only capability model.
