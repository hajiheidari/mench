# Basic tournaments (M14)

Registered players can create/join4/8/16/32-player single-elimination brackets. Each match is two-player. One active bracket per host; host starts only when full, and may cancel an unstarted lobby. Join order is public seeding, not a claimed random draw. Blocks prevent registration/start involving blocked accounts. Outsiders may preview invited lobbies; running/finished brackets are member-only. No entry fees, stakes, real-money prizes or tournament bonus claims.

@mench/tournament is a pure independent state machine. Backend holds the durable JSON bracket and a unique game-to-match mapping. Clients never submit winners. Assigned opponents create/join a normal casual2-player room, then link its code before starting. Backend locks the actual saved room and checks both authenticated account IDs against the assigned pair, capacity, phase and mode. A game can belong to one bracket match only. Final authoritative game snapshot/result/rewards and bracket advancement commit in one transaction. Repeated result writes do not advance twice. Room lock precedes bracket lock to avoid inversion with result settlement.

Web/Expo account views display membership, rounds, current assigned pair, room linking and champion. Brackets refresh every5s while running. Gameplay uses existing room invitations/reconnect, dice proofs and server authority. This deliberately basic workflow requires linking before start; automated room orchestration, scheduled starts, push notifications, byes/seeding rules, forfeits/timeouts and tournament-specific prizes remain future work. An abandoned or expired linked game stalls its bracket; no invented winner is awarded. Account-deletion/retention review and moderation cancellation of live brackets remain release requirements.

Pure tests complete all4/8/16/32 brackets and reject duplicate/conflicting results, wrong phase and reused games. PostgreSQL integration covers host/membership access, concurrent joins/capacity, forged result fields, authenticated room matching and three complete real-WebSocket games through both semifinals and final, checking every dice proof. Browser acceptance exercises four registered account UIs through join/start/reload of a persisted bracket. Native JS exports verify compilation, not device execution.
