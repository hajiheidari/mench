## Android emulator acceptance (2026-10-09)

Google emulator37.2.12 and the official Android29 default x86_64 image run headlessly with `-accel off -gpu swiftshader`. An AVD using Pixel2 geometry (1080x1920) was created under /tmp/mench-avd. Initial Persian launch/scroll was checked at420dpi; the interaction checks used240dpi so the board and controls fit together. System images/download staging use /tmp/mench-android-sdk because the checkout disk lacked extraction space. These are temporary test resources, not a claim of restored/snapshotted emulator readiness.

Build the emulator variant with `MENCH_ANDROID_ARCHITECTURE=x86_64 python3 infra/scripts/build-android-development.py`, then preserve its app-release.apk before the ARM64 build overwrites that generated output. Default invocation still builds ARM64 for phones. Both variants contain the same SHA256-verified Hermes game bundle. The new phone artifact is /workspace/mench-artifacts/mench-android-v2.apk; the emulator artifact is /workspace/mench-artifacts/mench-development-emulator-x86_64.apk.

Use ANDROID_HOME=/workspace/mench-toolchains/android, ANDROID_USER_HOME=/workspace/mench-toolchains/android-user, ANDROID_EMULATOR_HOME=/workspace/mench-toolchains/android-user and ANDROID_AVD_HOME=/tmp/mench-avd. Launch `emulator -avd mench-test -no-window -no-audio -no-boot-anim -no-snapshot -gpu swiftshader -accel off -memory 2048 -cores 2`. Wait for `adb -s emulator-5554 shell getprop sys.boot_completed` to return1 before installing. Then use `adb install -r <emulator-apk>` and `adb shell am start -W -n com.mench.game/.MainActivity`. Managed filesystem restrictions initially blocked the emulator's configuration directory; approved outside execution and the supported ANDROID_EMULATOR_HOME override resolved startup.
