# Accounts (M6)

PostgreSQL users/session tables are installed by checksum-verified migration 001 in a transaction under advisory lock. Migration rerun is tested. Passwords use asynchronous scrypt N=32768,r=8,p=1, unique 128-bit salts and constant-time comparison. Never store plaintext passwords. Missing users still run the same KDF.
Browser sessions are random 256-bit capabilities, only SHA256 stored in DB, HttpOnly/SameSite=Strict cookies, Secure in production. Expire after 30 days; logout revokes token; password-confirmed deletion removes account and all sessions. Mutating API requests reject foreign browser origins. Register/login rate limited. Native login may request x-client-platform:mobile and use bearer token; native UI must store it in SecureStore, never logs or invitation URL.
Authenticated sockets resolve account identity from existing cookie/bearer at handshake; account ID is internal and cannot be chosen by clients. Registered player cannot join twice in a room with the same account. Guests still use separate room-scoped capabilities. Account profile is shared across clients; gameplay statistics/economy are later milestones, not fabricated here.
Public profiles contain only id/name. /api/me exposes email only to authenticated owner. UI handles registration/login/logout/deletion. Email verification/password recovery and Google/Apple are not implemented; cannot claim email ownership verification or production account readiness. Registration conflicts can reveal account availability; evaluate enumeration protections before production.
API runs without a database only in explicit test factories; development entrypoint uses the documented local PostgreSQL URL, production requires DATABASE_URL. Production TLS configuration must remain verified.
